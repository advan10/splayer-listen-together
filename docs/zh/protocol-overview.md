# 协议概览与鉴权

一起听服务端与插件之间的全部接口都是 HTTP + JSON。网页端复用其中只读的部分，另用一条 SSE 流实时刷新（见[接口参考](protocol-endpoints.md#get-apiroomroomidevents网页端-sse-流)）。

## 通用约定

- 基础路径：`http://<host>:<port>/api`，默认端口 `8788`
- 请求与响应均为 JSON
- 时间单位：**毫秒**
- 时间戳：Unix 毫秒（`Date.now()`）
- 字段命名：小驼峰

「线上格式」的权威类型定义在 [`server/src/types.ts`](../../server/src/types.ts)。插件是单文件纯 JS、无法 import，脚本里有一份等价的手写定义，两边需要同步修改。

## 鉴权：服务端密钥

服务端设置了 `SERVER_KEY` 环境变量之后，**除 `/api/health` 外的所有接口**都必须带上这个密钥，否则返回 `401 SERVER_KEY_REQUIRED`。

两种携带方式：

| 方式 | 场景 |
| --- | --- |
| 请求头 `X-Server-Key: <密钥>` | 插件走这条 |
| 查询参数 `?key=<密钥>` | 浏览器走这条 —— `EventSource` 设不了请求头 |

比较使用恒定时间实现（`timingSafeEqual`），避免从响应耗时反推密钥。

`/api/health` 是例外，始终开放：它是给容器探活用的。但设置了密钥之后，它只返回 `version` / `uptimeMs` / `serverTime`，不再返回房间数量。

> **别把这个当成强鉴权。** 密钥是**共享密钥**，拿到它的任何人都能建房间、进房间。
> 它拦的是「没拿到密钥的陌生人」，不是「拿到密钥的坏人」。
> 另外 `clientId` 与 `hostToken` 都不是凭据签发的 —— 拿到密钥的人可以冒用别人的 `clientId`。
> 给朋友之间用足够了，别拿它当多租户隔离。

## 错误信息本地化

服务端的 API 错误文案与控制台输出由 `LOCALE` 环境变量决定：`zh_cn`（默认）/ `en_us`（大小写与连字符写法均可接受，如 `en-US`）。语言在进程启动时确定一次，不做按请求的语言协商。

因此**客户端应以错误响应中的 `code` 字段为准**，`error` 文案只用于展示给人看。错误码总表见[数据结构与错误码](protocol-types.md#错误响应)。
