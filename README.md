# 一起听（Listen Together）

用 **SPlayer-Next 控制插件 + 自建同步服务端**，让几个人在各自的电脑上听同一首歌。

- 谁在放歌，就把曲目、播放态、进度上报到服务端；其他人订阅并自动对齐；
- 房间有**两种控制模式**：`只有房主可调`（默认，房主放什么大家听什么）和
  `大家都可以调`（谁都能换歌，其他人跟着切——最后动手的人说了算）；
- 开了 MCP 之后，换歌时其他人也会自动切过去；
- 还有一个网页房间页，谁在听什么一眼可见。

默认面向**网易云音乐**（SPlayer 的 `netease` 音源）。

```
┌──────────────┐   上报播放状态    ┌──────────────┐   长轮询下发    ┌──────────────┐
│  SPlayer     │ ───────────────► │   服务端      │ ─────────────► │  SPlayer     │
│  房主插件     │                  │  （本仓库）   │                │  听众插件     │
└──────────────┘                  └──────┬───────┘                └──────┬───────┘
                                         │ SSE                          │ 本机 MCP
                                         ▼                              ▼
                                  网页房间页                  play_track（自动切歌）
```

---

## ⚠️ 先看这个：自动切歌为什么需要 MCP

SPlayer-Next 的**控制插件 API 里没有「播放指定曲目」**——只有
`play` / `pause` / `next` / `prev` / `seek` / `setVolume`。
外部 HTTP API 和 WebSocket API 也一样没有。

唯一能「点名播某首歌」的本地入口是 SPlayer 内置的 **MCP 接口**，
它的 `play_track` 工具支持直接传一条完整 Track 对象。
所以插件在需要切歌时，是通过 `http://127.0.0.1:<MCP端口>/mcp` 调 `play_track` 实现的。

这意味着：

| 想实现的效果 | 需要什么 |
| --- | --- |
| 看到房间在听什么、进度条、成员列表 | 什么都不用额外开 |
| 暂停/继续时其他人跟着暂停/继续 | 什么都不用额外开 |
| **播放同一首歌时**进度自动对齐 | 什么都不用额外开 |
| **换歌时其他人也切过去** | 开启 MCP，并把端口和密钥填进插件设置 |

没开 MCP 也能用，只是换歌时要自己点一下（插件菜单里有「立即同步」）。

## 快速开始

### 1. 起服务端

需要 **Node.js ≥ 22.18**（直接跑 TypeScript，无需构建）。

先把配置模板复制一份，填上自己的密钥：

```bash
cp .env.example .env.local
```

然后启动：

```bash
npm start
```

`.env.local` 不进版本库，`npm start` 会自动读它。如果想跳过这一步、直接把配置写在命令行上：

```bash
SERVER_KEY=换成你自己的密钥 node server/src/index.ts
```

`SERVER_KEY` 是**服务端密钥**：设了之后所有接口都要带对才能访问，插件里填同一个值就行。
**不设的话，任何人只要能连到这个端口，就能随便创建房间。**

看到这样就算好了：

```
  一起听服务端 v0.2.1 已启动
  房间列表  http://127.0.0.1:8788/
  房间页面  http://127.0.0.1:8788/room/<房间ID>
  健康检查  http://127.0.0.1:8788/api/health
  服务端密钥 已开启：插件要填对密钥才能连上
```

想换端口或额外给房间上锁，都在 `.env.local` 里改（见 [服务端配置](#服务端配置)）。

> **`SERVER_KEY` 和 `ROOM_KEY` 不是一回事**：前者是「谁能用这台服务端」，
> 后者是「谁能进这个房间」。自己人用的话设一个 `SERVER_KEY` 就够了；
> 想在同一台服务端上区分不同小圈子，再给各自的房间配 `ROOM_KEY`。

### 2. 安装插件

SPlayer-Next → **设置 → 插件管理 → 本地导入**，选 [`plugin/splayer-listen-together.js`](plugin/splayer-listen-together.js)。

安装后插件会自动启用。

### 3.（听众需要）开启 MCP

只有在需要**自动切歌**时才做：

1. SPlayer-Next → **设置 → AI 集成 → MCP** → 打开服务，记下端口（默认 `14559`）；
2. 打开「配置详情」，复制里面的 `X-MCP-Key`；
3. 回到插件设置，打开「允许经 MCP 自动切歌」，把端口和密钥填进去。

### 4. 配置插件

在插件卡片的「设置」里填：

| 设置项 | 说明 |
| --- | --- |
| 服务端地址 | 服务端根地址。同一个局域网填 `http://<服务端内网IP>:8788` |
| 服务端密钥 | 服务端设了 `SERVER_KEY` 时必填，填同一个值；没设就留空 |
| 房间 ID | 同一个 ID 的人在同一个房间，字母/数字/`_`/`-` |
| 房间口令 | 可选。第一个人填了之后，其他人必须填一样的 |
| 昵称 | 显示在成员列表里，留空自动生成 |
| 角色 | `自动`（默认，没人当房主就顶上）/ `房主` / `听众` |
| 控制模式 | `只有房主可调`（默认）/ `大家都可以调`，见下一节 |
| 自动跟随切歌 | 换歌时也切过去（需要 MCP） |
| 同步播放/暂停 | 跟着当前的播放态 |
| 同步播放进度 | 偏差超过阈值才跳转 |
| 进度对齐阈值 | 默认 2000ms。调小更同步，但会频繁跳转 |
| 上报间隔 | 默认 5s，没有歌词事件时靠它兜底刷新进度 |

## 两种控制模式

房间有一个「控制模式」，决定**谁能决定听什么**。它是房间属性，在房间创建时按第一个人的设置确定，之后房主可以随时用菜单切换。

| 模式 | 行为 |
| --- | --- |
| **只有房主可调**（默认） | 只有房主能换歌、暂停、拖进度。听众在本地怎么点都不会影响房间——他就是来跟着听的。 |
| **大家都可以调** | 谁都能换歌、暂停、拖进度，其他人自动跟着切过去。 |

「大家都可以调」不是让所有人各放各的——那样几个人会互相抢进度、谁都听不完整。
这里的规则是**谁最后动手谁在控**：

- 你在本地换了首歌，这一下就会被当成「我要放这个」，其他人跟着你切；
- 别人动手之后，你这边自动让出控制权，安静跟随，不会再把自己的状态报回去；
- 当前谁在控，房间页面上会标出来（成员列表里的「在控」标签）。

所以它是一个「接力」而不是「抢麦」：任何时候都只有一个权威播放状态，大家听的是同一份。

房间默认是「只有房主可调」。想换成大家一起调：

1. 插件设置里把「控制模式」改成「大家都可以调」（房主改，会立刻生效）；
2. 或者随时用菜单 **一起听：切换控制模式**——房主点一下就切，听众点会提示「只有房主能改控制模式」。

> 非房主想拿回控制权的话，先用「一起听：我当房主」接管房主位，再切模式。

### 5. 开始一起听

房主那边正常放歌就行。其他人把「房间 ID」填成一样、口令填成一样，就进来了。

插件菜单（歌曲右键 / 底栏「更多」里的插件子菜单）里有：

- **一起听：状态** —— 我是什么身份、房间处于什么模式、几个人、在放什么、是不是我在控
- **一起听：立即同步** —— 上报一次当前状态 / 立刻跟一次
- **一起听：切换控制模式** —— 在「只有房主可调」和「大家都可以调」之间切换（房主才能改）
- **一起听：我当房主** —— 顶掉现任房主，换成自己
- **一起听：打开房间页面** / **复制房间链接**

## 网页端

两个页面：

| 地址 | 内容 |
| --- | --- |
| `http://<服务端>:8788/` | **房间列表** —— 这台服务端上现在有哪些房间、各在放什么 |
| `http://<服务端>:8788/room/<房间ID>` | **房间详情** —— 当前曲目、封面、进度条、成员、谁在控 |

房间详情用的是 SSE，页面自己会重连；房间列表每 5 秒刷一次，正在播的排在最前面。

### 密钥怎么看

**链接里不带密钥。** 服务端设了 `SERVER_KEY` 的话，页面会先弹一个输入框让你填，
填对了记在浏览器里，之后同一个浏览器直接打开就能看。

这样分享出去的地址是干净的（`http://<服务端>:8788/room/xxx`），密钥各人自己知道就行。
如果收到的链接恰好带了 `?key=xxx`，页面上会用它、然后把它从地址栏抹掉——但不需要这么做。

> 网页只是**看板**：浏览器里听不了歌，真正的声音在各人的 SPlayer 里。

## 服务端配置

全部走环境变量，都有默认值。

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | `8788` | 监听端口 |
| `HOST` | `0.0.0.0` | 监听地址。只想本机访问就填 `127.0.0.1` |
| `SERVER_KEY` | 空 | **服务端密钥**。设了之后所有接口都要带对才能访问；不设就是谁都能建房间 |
| `ROOM_KEY` | 空 | 全局房间口令，设了之后所有房间都要带（和 `SERVER_KEY` 是两道独立的门） |
| `MEMBER_TTL_MS` | `60000` | 多久没心跳算离线；房主离线后别人可以接管 |
| `ROOM_TTL_MS` | `43200000` | 空房间保留多久（12 小时） |

`SERVER_KEY` 设了之后，`/api/health` 仍然对外开放（容器探活要用），
但它只返回版本和运行时长，不含房间数量。

### Docker

```bash
docker compose up -d
```

或者：

```bash
docker build -t listen-together .
docker run -d -p 8788:8788 -e ROOM_KEY=my-secret listen-together
```

## 排错

**插件状态是「已就绪」但房间页一直是空的**

看插件日志（应用主日志在 `{userData}/app-data/logs/`）。常见原因是服务端地址填错，
或者开了「详细日志」之后能看到具体报错。插件菜单里的「一起听：状态」会直接告诉你原因。

**状态里显示「服务端密钥不正确」**

服务端起了 `SERVER_KEY`，但插件里的「服务端密钥」没填或填错了。填成一样的值，
保存后插件会自动重连，不用重装。

**听众一直不切歌**

1. 确认 SPlayer 的 MCP 服务开着（设置 → AI 集成 → MCP）；
2. 确认插件的「允许经 MCP 自动切歌」开着，端口和密钥填对了；
3. 密钥错了会报 `MCP 密钥不正确`，在插件状态里能看到。

**听众比房主慢半拍 / 老是跳进度**

调小「进度对齐阈值」会更同步但跳得更勤，调大则相反。
长轮询的传播延迟通常在 1 秒内，加上网络抖动，实际同步误差一般在 1 秒上下。

**局域网里连不上**

服务端默认监听 `0.0.0.0`，确认防火墙放行端口，插件里的地址用内网 IP 而不是 `127.0.0.1`。

## 开发

`server/src/` 下的代码用 Node 原生类型剥离直接运行，**没有构建步骤、服务端零运行时依赖**。
网页那三个文件也是原样下发的，改完刷新浏览器就能看到。

```bash
npm start                           # 起服务端（读 .env.local）
npm run dev                         # 改代码自动重启
npm install && npm run typecheck    # 类型检查
npm test                            # 跑下面两个测试
npm run demo                        # 造一间演示房间，浏览器打开看界面
```

两个测试脚本（都需要服务端先跑起来）：

| 脚本 | 作用 |
| --- | --- |
| [`scripts/check-plugin.mjs`](scripts/check-plugin.mjs) | 用 `node:vm` 搭一个假的 `splayer` 环境真实加载插件：校验脚本头部、`register()` 的声明（事件名、设置项 schema、菜单项），并跑通「房主上报」「听众经 MCP 自动切歌」「两种控制模式的差别」几条路径 |
| [`scripts/simulate.mjs`](scripts/simulate.mjs) | 扮演房主 + 听众两个假客户端，把服务端流程跑一遍（上位、长轮询、进度推算、换歌、乱序丢弃、控制模式、房主交接），再单独拉临时服务端验证超时释放与密钥门禁 |

改完服务端先跑 `npm run test:server`，改完插件先跑 `npm run test:plugin`。

`npm run demo` 会往房间 `demo` 里塞一个房主和三个听众，方便对着真实数据调网页界面；
加 `--paused` 看暂停态，加 `--mode host` 看「只有房主可调」。
